# 让 Claude 直接上手远端机器 —— Remote Assist Tool 使用

> 一条命令，把你的 Claude Code 变成一个能**自己动手**调试远端机器的工程师：
> 远端不用装 SSH server、不用开端口、不用配账号，
> 你只要说一句「协助码 ABCD-EFGHIJ，连上去看看」，剩下的它自己干。

---

## 1. 它解决了什么痛点

平时远程排查一台机器（同事的电脑 / NAT 后的测试机 / 客户现场的服务器），你大概率要经历：

- 在远端折腾 `openssh-server`、改防火墙、开端口映射；
- Windows 上根本没有顺手的 SSH，还要装第三方；
- 连上之后，**所有命令还得你一条条敲**，Claude 只能在旁边出主意，碰不到真机。

**Remote Assist Tool 把这些全干掉了：**

| 传统方式 | 本工具 |
|---|---|
| 远端装 SSH server、开端口 | 远端跑一条 `remote share` 就行 |
| 你手动敲命令，Claude 旁观 | Claude 直接调用工具，**自己 exec / 读文件 / 看进程 / 追日志** |
| 公网才能连 | 公网 relay / **局域网 standalone** 两种部署，relay 模式下还会自动 P2P 打洞优化 |
| 平台割裂 | Windows / Linux / macOS / ARM 全平台二进制 |

一句话：**它不是给你一个远程终端，而是给 Claude 一双能在远端机器上动手的「手」。**

---

## 2. 核心能力：Claude 自动定位远端问题

配对成功后，Claude Code 的 `/mcp` 里会出现一组直接作用于**远端机器**的工具：

| 工具 | 作用 | 典型用途 |
|---|---|---|
| `connect` | 用协助码完成握手（可选覆盖 relay 地址） | 会话开始 |
| `exec` | 远端执行 argv（**不过 shell**，更安全） | 跑 `go vet`、`systemctl status`、`tasklist` |
| `read_file` / `write_file` | 受沙箱保护的远端读写 | 看配置、改一行修复 |
| `list_dir` / `stat` | 列目录 / 查元信息 | 摸清项目结构 |
| `glob` / `grep` | 远端文件系统搜索 | 全盘找报错关键字 |
| `process_list` | 远端进程清单 | 看谁占了端口、谁挂了 |
| `tail_log` | 读取日志末尾 N 行（默认 100） | 看最近的报错栈 |

**实际对话长这样：**

```
你：协助码 ABCD-EFGHIJ，连上去。服务起不来，帮我看看为什么。

Claude：
  → connect("ABCD-EFGHIJ")                 ✅ 已连接
  → process_list(filter="myapp")           没看到进程，确实没起来
  → tail_log("/var/log/myapp/error.log", lines=50)
                                            发现 "bind: address already in use"
  → exec("ss", ["-ltnp"])                  8080 被 nginx 占了
  → 结论：端口冲突。要不要我把 myapp 的监听端口改成 8081？
```

整个过程你**没敲一条远端命令**，Claude 自己定位、自己取证、给结论。

## 3. 三种使用模式，按场景挑

### 模式 A：标准模式（有公网 relay，推荐日常用）

适合：远端在外网 / 跨 NAT，你有一台公网中转服务器（relay）。

**① 远端跑 share（被协助端）**

```bash
# 限定沙箱根目录为待排查的项目
remote share --server relay.example.com:8443 --insecure
# 或者直接执行默认就是share
remote
```

控制台打印协助码，例如 `ABCD-EFGHIJ`，30 分钟内有效。

**② 本地配置 Claude Code（一次性）**

项目根 `.mcp.json` 或 `~/.claude/mcp.json`：

```jsonc
{
  "mcpServers": {
    "remote-debug": {
      "command": "D:\\path\\to\\remote-windows-amd64.exe",
      "args": ["help", "--mcp-stdio"]
    }
  }
}
```

> 关键：**不带 `--code`** —— 这是 **bootstrap 模式**。MCP server 先启动，
> 协助码在每次会话里通过 Claude 的 `connect` 工具临时提供，**换机器、换会话都不用重启 Claude**。

**③ 在 Claude 里直接说**

```
协助码 ABCD-EFGHIJ，连上去
```

Claude 调用 `connect("ABCD-EFGHIJ")` 完成握手，之后所有工具直通远端。

---

### 模式 B：standalone 局域网模式（没有公网服务器也能用）⭐

适合：远端和你**在同一局域网**（公司内网 / 同一 WiFi），手头**没有公网 relay**。
share 进程会**自己内嵌一个 relay**，省去单独部署服务器这一步。

**远端只跑一条命令：**

```bash
remote share --standalone
```

它会自动：内嵌 relay → 监听局域网 → 探测本机内网 IP，并打印：

```
================ standalone (LAN) mode ================
Relay listening at: 192.168.1.50:8443 (LAN reachable)
After you see 协助码 below, tell Claude:
    "协助码 <code> 在 192.168.1.50:8443"
=======================================================

协助码已生成: ABCD-EFGHIJ
```

**本地在 Claude 里说：**

```
协助码 ABCD-EFGHIJ 在 192.168.1.50:8443
```

Claude 调用 `connect(code="ABCD-EFGHIJ", server="192.168.1.50:8443")`，
`connect` 支持 **server 覆盖**，临时指向局域网那台机器，**完全绕开外部 relay**，本地 `.mcp.json` 一个字都不用改。

> standalone 模式自动启用 `--plain`（局域网场景），但工具通道仍用协助码派生的
> session_key 做 XChaCha20-Poly1305 AEAD 加密，内容不会被中间环节看到。

---

### 模式 C：旧 SSH 隧道模式（向后兼容）

如果你就是想要一个传统的 SSH 端口转发（远端有 sshd），原功能完整保留：

```bash
# 远端
remote share --server relay.example.com:8443 --insecure
# 本地（注意不带 --mcp-stdio，或显式 --legacy-ssh）
remote help --server relay.example.com:8443 --code ABCD-EFGHIJ --insecure
# 然后
ssh -p 2222 user@127.0.0.1
```

## 4. 五分钟上手清单

1. **拿二进制**：`bin/` 下已有全平台预编译版本，按机器选：
   - Windows: `remote-windows-amd64.exe` / `remote-windows-arm64.exe`
   - Linux: `remote-linux-amd64` / `remote-linux-arm64` / `remote-linux-armv7`
   - macOS: `remote-darwin-arm64`
   - 自己编：`go build -o bin/remote ./cmd/remote`
2. **本地配一次 `.mcp.json`**（见模式 A，bootstrap 写法）。
3. **远端跑 `remote share`**（想把文件工具限制在某目录可加 `--root <目录>`），拿协助码。
4. **在 Claude 里说「协助码 XXXX，连上去」**，开干。

> 想更省事，可以把「连接 + 例行排查」固化成一个 Claude Code skill / slash 命令，
> 让 `/remote-debug ABCD-EFGHIJ` 一步触发 connect + 初步体检。工具本身已经把能力暴露成 MCP，
> 包装成 skill 只是顺手的事。

## 5. 自部署 relay（公网中转）

只在「跨公网/跨 NAT」时才需要，局域网用模式 B 即可跳过。

**生成证书 + 启动：**

```bash
# 生成自签名证书（开发/自用）
relay --gen-certs --certs-dir ./certs

# 启动（TLS）
relay --listen :8443 --cert ./certs/server.crt --key ./certs/server.key
```

**Linux 服务器后台常驻：**

```bash
nohup ./relay-linux --listen :8443 \
  --cert ./certs/server.crt --key ./certs/server.key > relay.log 2>&1 &
echo $! > relay.pid
```

**relay 常用参数：**

| 参数 | 默认 | 说明 |
|---|---|---|
| `--listen` | `:8443` | 监听地址 |
| `--cert` / `--key` | - | TLS 证书 / 私钥 |
| `--ttl` | `30m` | 协助码有效期 |
| `--audit` | `audit.log` | 审计日志 |
| `--gen-certs` | - | 生成自签名证书后退出 |
| `--plain` | `false` | 非 TLS（仅开发） |

> relay **只做中转**：协助码握手后，工具流量已被端到端 AEAD 加密，relay 看不到内容、也无法伪造请求。
> 开放防火墙 8443 端口即可对外服务。

## 6. 安全模型：能放心交给 Claude

| 机制 | 作用 |
|---|---|
| **协助码 30 分钟 TTL + 单次配对** | 码泄露窗口极小，连上后 share 端会显示对端版本可供核对 |
| **`--root` 路径护栏（可选）** | 设了才生效：文件工具锁在该子树，越界返回 `path_outside_root`。**不约束 exec**，故只防手滑、不防恶意 |
| **exec 不过 shell** | 直走 argv，无 `cmd /c` / `bash -c` 注入面 |
| **`--deny-exec` 默认黑名单** | 默认拦 `rm,shutdown,reboot,mkfs,dd`；可加 `--allow-exec` 白名单 |
| **端到端 AEAD（XChaCha20-Poly1305）** | 工具内容只有两端能解，relay 不可见、不可改 |
| **share 端实时显示每条调用** | 远端每次 exec/读写都打印在 share 终端，当面可见（relay 另有会话级审计日志） |
| **`--unsafe-exec`** | 关掉 exec 黑/白名单，启动强制 5 秒红色倒计时确认；不影响 `--root` |
| **`--elevate`（Windows）** | 需管理员权限时显式 UAC 提权，不默认提权 |

**信任边界是协助码，不是沙箱**：share 由你主动发起、码有 30 分钟 TTL，码交给谁就等于把这台机器交给谁 —— 因为 exec 能跑任意程序，`--root` 拦不住它（`sh -c 'cp ... <root>/'` 一句即绕过）。上表的护栏防的是**手滑**（Claude 跑偏、误删误写），不是恶意方。这也是默认不限制文件路径的原因：既然拦不住恶意方，就不该用它给正常调试添堵。

真要防不完全信任的对端，别指望进程内沙箱 —— 把 share 跑在**容器或专用低权限账号**里，那才是真隔离。

| 维度 | 本工具 | frp | ngrok | Tailscale |
|---|---|---|---|---|
| 核心定位 | **Claude 直接操作远端 + 临时协助** | 反向代理 | 内网穿透 | 虚拟组网 |
| Claude 能否动手 | ✅ connect + 9 个远端工具 | ❌ | ❌ | ❌ |
| 远端是否要 SSH server | ❌ 不需要 | - | - | - |
| 局域网零服务器 | ✅ standalone 内嵌 relay | ❌ | ❌ | P2P |

**它的独特价值**：别的工具给你「通道」，本工具给 Claude「能力」——直接把 exec/文件/进程/日志变成 Claude 手里的工具，专为「让 AI 自己定位远端问题」设计。

## 8. 常见问题

- **远端要管理员吗？** 不要。默认在当前用户上下文跑，能读用户目录、跑 `tasklist`/`ps`、读大部分日志。需要更高权限再加 `--elevate`。
- **换一台远端要重配 Claude 吗？** 不用。bootstrap 模式下，新协助码直接在对话里告诉 Claude 即可，`connect` 还能临时覆盖 relay 地址。
- **断线了怎么办？** 隧道中断后正在进行的工具调用会返回 `tunnel_lost`；重新对 Claude 说一句「协助码 XXXX 连上去」即可重新握手（`connect` 会自动关掉旧连接再建新的）。
- **协助码过期了？** 远端重跑 `remote share` 拿新码，再说一句「协助码 XXXX 连上去」即可。
- **流量安全吗？** 工具内容端到端 AEAD 加密，relay/中间网络都看不到；standalone 局域网模式同样加密。
